# 竞品分析 · Typeless

> 来源：Kimi PRD 头号竞品研究（PRD v2.0 §1.1）
> 状态：初步调研，待实测验证

## 基本信息

| 项 | 值 |
|---|---|
| **官网** | typeless.com |
| **形态** | 云端语音键盘（按住说话→润色成稿） |
| **平台** | macOS / Windows / iOS / Android |
| **核心动作** | 按住 Fn 说话 → 松手成稿 → 写进当前输入框 |
| **定价** | Pro $12/月（年付）/$30/月（月付） |

## 商业模式

- **免费版**：8,000 词/周
- **Pro**：按月/年订阅
- 不支持 BYOK——全部走自己云端 + 自有 LLM（推测混元或自研）

## 关键漏洞（译语的可乘之机）

### 1. BYOK 不支持
用户没法用自己的 API Key，意味着：
- 数据必然经 Typeless 云端
- 用户被锁死在 Typeless 的模型选择上
- 不可定制 prompt / 术语表

**译语对策**：任意 OpenAI 兼容协议 + 自定义 BaseURL，把控制权交还用户。

### 2. 不支持 Linux / 不支持本地离线
- Typeless 是云端 SaaS，无离线模式
- 没有 Linux 客户端

**译语对策**：Ollama / 端侧 MLC LLM + 本地 Whisper——纯本地可用。

### 3. 隐私争议
- 为做上下文感知，Typeless **采集输入框周边文本**
- 单次会话硬限 6 分钟（会话超时）

**译语对策**：零采集（写进隐私政策）、不设时长硬限（受限于模型上下文即可）。

### 4. iOS 切换键盘摩擦
差评重灾区：
- 系统不允许自动切换键盘，要用户手动切
- 占用表情键 → emoji 用户怨声载道

**译语对策**：
- 引导教程 + 显眼的大切换键
- 不占用 emoji 键位，译语键放工具条左侧
- App 内语音翻译兜底（键盘内不录语音）

## 对译语设计的具体启示

1. **按住 Fn 说话**这个交互形态已被市场验证，可以直接复用
2. **1.2s 后悔窗口**比 Typeless 的"直接写入"更友好，但给用户可选项
3. **预览期可改口指令**（"不对，改成……"）应保留——对齐 Typeless 的 self-correction
4. **Typeless 同款两步权限引导**（macOS 辅助功能+输入监控）要抄
