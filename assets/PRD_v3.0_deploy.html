1. 产品概述

1.1 一句话定位

按住说话（或打一句话），译文自动落进你正在输入的地方——用你自己的模型 Key，离线也能用。

1.2 三大支柱

  1. BYOK：任意模型平台 Key 自由配置（OpenAI 兼容 / Anthropic / Gemini / 自定义 BaseURL）
  2. 全平台 + 离线：macOS / Windows / Linux / iOS / Android 五平台覆盖；支持 Ollama 本地模型、Whisper 本地转写
  3. 隐私优先：数据不出本机，流量直连模型方，零遥测

1.3 目标用户

  • 跨语言办公/学习者
  • 出海从业者、跨境电商客服
  • 多语开发者、隐私敏感人群
  • iOS/Android 移动端跨语沟通

2. 核心使用流程 (六大流程)

流程 A：按住说话 → 译文落框 P0

场景：用户在 WhatsApp/Telegram/邮件里给外国客户发消息

① 光标在任意输入框
② 按住 Fn（默认，可改）→ 屏幕底部浮出细录音条（波形动画 + 计时）
   说中文："那个报价我确认没问题，下周三之前可以签合同"
③ 松开 Fn → 录音条变"转写/翻译中"状态条（显示已输出字符数）
   - 语音转写（本地 Whisper 或用户配置的 STT API）
   - 自动去口头禅、补标点、按语境成稿
   - 翻译成目标语言，流式输出
④ 状态条预览译文 1.2 秒（可点展开编辑）→ 自动写入输入框并消失
   Esc 随时取消

关键规则：

  • 按住说话、松手成稿：过程中用户不离开当前应用，无悬浮窗打断
  • 预览期 1.2 秒 = "后悔窗口"；设置可改"直接写入"或"总是预览"
  • 长语音无 6 分钟硬上限（吸收 Typeless 痛点）
  • 中途说错 → 继续说"不对，改成……" — 成稿引擎只保留最终意图

流程 B：悬浮窗输入翻译 P0

⌥+空格 / Alt+空格 → 鼠标旁弹出迷你悬浮窗 → 直接打字/粘贴（自动读剪贴板）→ 流式显示译文 → Enter 写回并关闭；⌘/Ctrl+Enter 仅复制

流程 C：划词翻译 P0

选中任意应用文本 → ⌥+D / Ctrl+Alt+D → 选区旁浮出译文小窗 → 点空白关闭 / 点"替换"写回 / 点喇叭朗读

流程 D：静默替换翻译 P0

输入框敲好中文 → ⌥+回车 / Ctrl+Alt+回车 → 底部状态条显示进度（翻译中…已输出 N 字，可取消）→ 完成：原文被译文替换；期间切换焦点则终止并 toast

流程 E：截图 OCR 翻译 P1

⌥+S / Ctrl+Alt+S → 框选区域 → 悬浮窗双栏「原文 | 译文」，均可复制

流程 F：移动端键盘 P1

键盘模式：唤出「译语键盘」→ 顶部 36px 工具条（语言方向中→英可互换 / 翻译开关 / 🎤 / 大切换键）→ 打字中文 → 候选区流式出英文译文 → 点上屏

iOS 已知限制与对策（吸收 Typeless 差评第一痛）：

  • 系统不允许自动切换键盘 → App 内提供"引导开启键盘 + 添加到常用列表"教程；键盘上放显眼大切换键
  • 键盘内不能访问麦克风 → 语音翻译走"App 内录音 → 译语文本 → 分享/复制"流程；键盘内只做文本翻译
  • 不占用 emoji 键位，译语键放工具条左侧

4. 交互与热键设计

参照系：ChatGPT 桌面版（修饰键+空格唤起）、Bob/有道（Ctrl/⌥+Alt+字母翻译动作）、Typeless/Chatterfly（Fn 按住说话）。

功能macOSWindows / Linux参照
语音输入（按住说话）按住 Fn按住 FnTypeless / Chatterfly
唤起悬浮窗⌥ + 空格Alt + 空格ChatGPT 桌面版
划词翻译⌥ + DCtrl + Alt + DBob / 有道
截图翻译⌥ + SCtrl + Alt + SBob / 有道

交互规则：

  1. 全部可重绑，实时冲突检测（含微信截图 Ctrl+Alt+A 等常见占用提示）
  2. 唤起键单次触发、语音键按住触发，两类手感必须区分
  3. 静默替换进行中若焦点变化，立即终止并 toast
  4. 悬浮窗动画 ≤ 180ms（淡入 + 上移 8px），不抢焦点
  5. 热键全局生效：macOS 需引导开启"辅助功能 + 输入监控"权限

5. 设计风格规范

5.1 基调

轻盈、无侵入、半透明质感——"伴随型"软件的存在感必须低于宿主应用。
参考系：Chatterfly（浅色圆角卡片 + 柔和蓝紫渐变）、Bob（紧凑悬浮窗）、Typeless（极简录音条）。

  • 圆角：悬浮窗 14px / 卡片 10px / 按钮 8px / 输入框 10px
  • 阴影：悬浮窗 24% 黑投影 (y8, blur24)
  • 尺寸：
    • 迷你悬浮窗 380 × 自适应 (min 120 / max 480px 滚动)
    • 划词小窗 320 × 自适应
    • 录音/状态条 280 × 32px，屏幕底部居中偏上 80px
    • 主窗口 960 × 640 (最小 720 × 480)

7. 异常与边界

场景处理
Key 无效 / 欠费 / 限流内联错误条显示模型方返回 + 直达配置页
断网提示切换"离线模式" (本地 Whisper + 本地 LLM 若已配置)
静默替换中焦点切换终止任务，toast 提示，原文不动
未配置任何模型默认引导"本地模型一键体验"，绝不白屏
隐私锁开启主窗需 FaceID/密码；悬浮窗功能不受影响
热键被占用设置页红字提示占用方
iOS 键盘未启用App 检测后弹引导，一键跳系统设置

8. 非功能需求

  • 性能：热键到窗口可见 < 150ms；首 token < 1.5s (主流 API)；录音条 60fps 波形
  • 隐私：零遥测默认；请求只发往用户配置的 BaseURL；不采集宿主应用任何上下文文本
  • 稳定性：热键监听崩溃自愈；更新不丢配置
  • 国际化：界面中/英双语
  • 可访问性：键盘可达性、VoiceOver 朗读、对比度 AA

9. 技术架构

Flutter (UI+业务) + 原生桥 (热键/剪贴板/焦点/IME/麦克风/钥匙串) + Provider 适配层 + SQLite + 系统密钥存储
流量直连模型方，无自有中转服务器。

项内容

12. 架构决策记录 (ADR)

ADR-001macOS 菜单栏范式 vs 独立窗口

日期：2026-09-26

决策：采用 macOS 原生范式——菜单栏常驻 + 浮窗 (Popover)，不是独立窗口 App。

理由：符合"伴随型"产品定位；菜单栏占用最小空间；Popover 模式更轻量。

影响：主窗口在 macOS 上是次要入口，主要交互通过菜单栏图标 + Popover 完成。

ADR-002原型 SPA App 化 vs 多页路由

日期：2026-09-26

决策：单 index.html + app.js + _shared.css (3 文件，无路由目录)，内部用 ⌘1-6 切换视图。

理由：原型阶段避免框架负担；所有交互在一个 HTML 里；更易部署和验收。

影响：v5 起所有视图统一到 SPA，URL hash 切换视图。

ADR-003Provider 接口设计原则 待定

决策：所有模型方实现统一 TranslationProvider 接口。

abstract class TranslationProvider {
  String get name;
  String get defaultBaseUrl;
  Stream<String> translate({
    required String text,
    required String sourceLang,
    required String targetLang,
    String? systemPrompt,
    String? glossaryJson,
  });
  Future<bool> testConnection();
  Future<List<String>> listModels();
}

待定项：错误模型 (ErrorCode 枚举)、重试策略、流中断恢复。

ADR-004录音条三态必须 first_frame 锚定

日期：2026-09-26 沉淀

决策：录音条说话/处理/预览三态的原型图必须三态并列展示，不能只画静态单态。

理由：三态切换是核心交互，单态会让验收者无法评估状态流转。

影响：v6 原型 Tab A 明确分三栏展示。
