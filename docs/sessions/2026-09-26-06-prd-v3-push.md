## 关键决策与理由

### 决策 1：PRD v3.0 主动按 R1 拆分（而非"先 push 再修"）
- **理由**：你给的反馈是"PRD §10/§11/§12 揉进去是错的，必须拆出来"——这正是 AGENTS.md R1 的要求
- **好处**：本次 push 完全合规，下一个 Agent 不需要再返工

### 决策 2：ADR 拆成 4 份而非合并为一份
- **理由**：仓库现有 ADR 都是一份一决策（ADR-001~004），保持一致性
- **替代方案**：合并为一份 `005-prototype-phase-decisions.md`（被否决：与现有 ADR 命名风格不符）

### 决策 3：v5 原型放 `prototypes/v5-spa/` 而非 `prototypes/` 根
- **理由**：[prototypes/README.md](../../prototypes/README.md) 有 v1~v3 老原型（`floating-window.html` / `recorder-bar.html` / `index.html`），新版本不能直接污染根
- **路径**：保留向下兼容，老 demo 不动；v5-spa 是新里程碑

### 决策 4：v6 完整 13 页原型暂不实施
- **理由**：你强调"用户先验收 v5，再决定 v6"，T-016 留作 ⬜ 任务
- **v5 实现了 7/13 tab**（A 录音条 / B 悬浮窗 / C 划词 / D 静默状态条 / E 截图 OCR / F 移动 App / G 移动键盘）
- **v6 需补 6 tab**：主窗首页 / 模型配置 / 快捷键 / 翻译偏好 + 术语 + Skills / 首次引导 / 托盘菜单栏

### 决策 5：CONTEXT/TASKS 标记 has_code: false（即便 push 了 HTML 原型）
- **理由**：R3 明确定义"产品代码"为可编译运行的 Flutter 工程；v5 SPA 是"原型层"，不属于产品代码
- **避免误解**：下一个 Agent 不会误以为可以开始 Phase 2（macOS MVP）
