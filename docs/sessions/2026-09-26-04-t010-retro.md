## 错在哪（5 维度复盘）

### 1. 竞品参照系错位 ❌ → ✅ 怎么改

- **错**：参照系停留在中文翻译 App 范式（有道、DeepL、谷歌翻译网页版）
- **应为**：这一类产品是「语音输入优先，翻译只是其中一个 feature」—— 真正的赛道是 Typeless / Wispr Flow / Spokenly / MacWhisper / Chatterfly
- **教训**：接到任务前必须先扫一遍同类产品的官网和 H2 顺序（功能排序），再决定设计方向

### 2. PRD §1 一句话定位权重失衡 ❌ → ✅ 怎么改

- **错**：原型把"翻译"做成主角（双语对比布局、原文+译文并排、C 位"🌐 语言切换"）
- **应为**：翻译只是众多模式之一（off / as-you-speak / after-dictation），主入口永远是「按住说话 → 写入输入框」
- **教训**：PRD 一句话定位里的"动词"决定 UI C 位——译语的核心动词是「写」（输入文字），不是「翻」（翻译）

### 3. 录音条 vs 悬浮窗的并列关系错 ❌ → ✅ 怎么改

- **错**：把录音条 + 悬浮窗做成并列组件，对应「录音」和「翻译」两个流程
- **应为**：录音条是**全场景常驻入口**（Typeless 式 pill），悬浮窗是**长录音 / 复杂场景下的展开态**（Spokenly 式中下方悬浮卡片）
- **教训**：组件并列 ≠ 用户流程并列。流程是「A 主 B 辅」（录音条常驻 + 悬浮窗按需展开），不是「A 切换 B」

### 4. 触发范式描述不清 ❌ → ✅ 怎么改

- **错**：PRD 暗示"按下 Fn → 录 → 译 → 写回"是单流程
- **应为**：触发可配置 + 模式可配置（按住 / 切换；不翻译 / 流式翻译 / 录音后翻译）；4 家产品都给"按住 or 切换"作为基本设置（Spokenly screenshots 明确证实）
- **教训**：触发和翻译模式必须是 Settings 里的两个独立可选项，不是绑死的

### 5. 视觉调研缺失 ❌ → ✅ 怎么改

- **错**：直接按 PRD §5 token 表画原型，没看真实同类产品的截图
- **应为**：先做 T-014（竞品视觉调研），再决定 token 表
- **教训**：PRD token 表是「我们以为的样子」，调研是「业界实际的样子」——后者必须先做

## 沉淀教训（写入 long-video-production skill 类同位置 / 写入 CONVENTIONS.md）

- **接到设计类任务前，先扫 3-5 个同类产品的真实截图 + H2 顺序（功能排序）**，再决定设计方向
- **PRD 一句话定位里的核心动词 = UI C 位的视觉对象**（写 → 输入框 C 位；翻 → 译文 C 位；说 → 录音条 C 位）
- **不要相信「文档写得很清楚」就先动手**——同类产品的真实形态可能跟文档的认知不一致
