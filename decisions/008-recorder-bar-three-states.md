# ADR-008 · 录音条三态原型必须并列展示 (说话 / 处理 / 预览)

- **状态**：✅ 已决策（2026-09-26，PRD v3.0 实施反馈）
- **影响 PRD**：§2 流程 A / §5.3 ① / §6 页面清单 #1 / §B.1 验收项

## 1. 背景

译语录音条是最高频核心组件（PRD §5.3 ①），用户每次翻译都触发。它有三种状态：

1. **说话态**：按住 Fn → 底部浮出 280×32 细条，主色波形动画 + 计时器
2. **处理态**：松开 Fn → 转写中/翻译中，显示已输出字符数，可点展开、可取消
3. **预览态**：翻译完成 → 1.2 秒后悔窗口，显示译文预览，自动写入

v1 原型（T-010）只画了"说话态"的静态截图，被用户否决（见 [`2026-09-26-04-t010-retro.md` §"组件关系"](../docs/sessions/2026-09-26-04-t010-retro.md) 教训：单态无法评估状态流转）。

## 2. 决策

**录音条三态在原型中必须并列展示**（三栏或三段），**禁止只画静态单态**。

### 展示规范

```
┌─ 说话态 ─────────┬─ 处理态 ─────────┬─ 预览态 ─────────┐
│ [◉ 波形]  00:07  │ [✕] 翻译中… 32字 →│ [✓] "Confirmed…" │
│ 主色波形 60fps   │ 可点展开可取消   │ 1.2s 后自动写入   │
│ 屏幕底部 +80px   │ 显示字数进度条    │ 可点编辑          │
└──────────────────┴──────────────────┴──────────────────┘
```

### 三态必须并列的强制项

- [ ] 三态外形尺寸、位置、动画一致（仅内容/图标/颜色变化）
- [ ] 三态之间的转移动画有说明（说话→处理：松开 Fn 触发；处理→预览：流完成触发；预览→消失：1.2s 后或 Esc）
- [ ] 1.2s 预览窗口的「后悔机制」在三态图上明确标注
- [ ] Esc 取消按钮在三态都要可见
- [ ] 三态图旁附简短文案说明每态触发条件与可执行操作

## 3. 理由

| 维度 | 单态 | 三态并列 ✅ |
|---|---|---|
| 验收者能否评估流转 | 否（看不到其他态） | **是** |
| 视觉一致性风险 | 高（每态独立设计） | **低** — 同框比照 |
| 交互文档完整性 | 缺 | **齐** — 完整闭环 |
| 实施沟通成本 | 高（需文字补充） | **低** — 一图胜千言 |
| 与用户痛点匹配 | Typeless 差评中"录音条不知道在不在工作"恰好对应处理态缺失 | **预防** |
