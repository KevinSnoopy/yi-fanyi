# ADR-005 · macOS 采用菜单栏范式 (menu bar + Popover) 而非独立窗口 App

- **状态**：✅ 已决策（2026-09-26）
- **来源**：PRD v3.0 实施反馈（用户提醒）
- **影响 PRD**：§1.2 三大支柱、§4 交互规则、§6 页面清单 #13

## 1. 背景

译语在 macOS 上的"主形态"有两条候选路径：

- **路径 A**：传统 macOS 应用——独立窗口 App（像 Typeless / Chatterfly / Bob / Typeless）
- **路径 B**：菜单栏常驻 + 浮窗（Popover）——像 1Password、CleanMyMac、Raycast、ChatGPT 桌面版

PRD v2.0/早期 v3.0 隐含走路径 A（"主窗口 960×640"，"桌面三端 (Win/macOS/Linux)"）。

## 2. 决策

**采用路径 B**：译语在 macOS 上是菜单栏常驻应用 + Popover，主窗口是次要入口。

- 菜单栏图标常驻显示当前状态（空闲 / 录音中 / 处理中）
- 用户点击菜单栏图标 → 弹出 Popover（迷你悬浮窗形态）
- Popover 内含核心交互：录音状态 / 原文 / 译文 / 复制 / 注入按钮
- 双击 ⌥ 唤起主窗口（用于：完整设置、首次引导、复杂配置）
- 红绿灯按钮的「关闭按钮」行为：最小化到菜单栏，**不退出进程**

## 3. 理由

| 维度 | 路径 A 独立窗口 | 路径 B 菜单栏 + Popover ✅ |
|---|---|---|
| 与"伴随型"产品定位匹配 | 一般 | **高** — 存在感低于宿主应用 |
| 占用桌面空间 | 窗口需占位 | **极小** — 仅菜单栏图标 |
| 用户切换应用时干扰 | 高（窗口抢焦点） | **低**（Popover 浮在菜单栏） |
| 录音条 + Popover 双形态切换 | 割裂 | **统一** — 录音条近似极简 Popover |
| 系统托盘习惯 | macOS 无托盘概念 | **完全 macOS 原生范式** |
| 唤起速度 | 需窗口动画 | **即时** — 点击即出 Popover |

## 4. 影响

- **架构**：菜单栏 daemon + Popover 渲染层（两者可能分离进程，菜单栏常驻、Popover 按需）
- **UI 资源**：主窗口从"必备"降级为"次要"，工作量减少；Popover 设计工作量上升
- **设计 Token**：Popover 复用 §5.3 ② 迷你悬浮窗规格（380×自适应）
- **PRD v3.0**：§1.2 三大支柱 / §4 交互规则 / §6 页面清单 #13 / §B.1 验收 B.7
- **跨平台**：Windows / Linux 采用对应原生范式（Windows 系统托盘 + 弹出 / Linux AppIndicator + 弹出）

## 5. 与其他 ADR 关系

- 不冲突 ADR-001~004
- 与 [ADR-006 SPA 原型](./006-prototype-spa-app.md) 配合：v5 SPA 内 ⌘1-6 切换视图的演示可同框展示 Popover + 主窗口
