# ADR-001 · 强制 BYOK，不做托管模型

> **状态**：已决策（PRD v2.0）
> **决策日期**：2026-09-26

## 背景

AI 输入助手有两条路：
1. **托管模型**（Typeless/Chatterfly 模式）：自带 LLM，按订阅收费
2. **BYOK**（Bring Your Own Key）：用户自己接 OpenAI/Anthropic/DeepSeek 等平台

## 决策

**选 BYOK**，但保留可选的"官方中转"作为给不愿折腾 Key 的用户的兜底（默认关闭）。

## 论据

### 选 BYOK 的理由

1. **隐私差异化**：用户的数据不经我们中转，只到模型方。这是 Typeless 等被点名的核心争议点，译语可以反着做
2. **解锁场景**：用户可以用本地 Ollama / 端侧模型（场景：跨境商务机密、离线、出国）
3. **不与用户争利**：用户自己付 token 费（DeepSeek 翻译一个月约 ¥1–5），我们赚的是工具钱
4. **Provider 多样性**：不被单一厂商绑死，可快速跟进新模型

### 反对意见（备选考量）

- ❌ **冷启动不友好**：新用户需要先有 OpenAI/DeepSeek Key 才能用——门槛
- ✅ 缓解：首次引导默认"先用本地模型试用"（Ollama 一键安装），零门槛体验
- ❌ **用户 Key 泄露风险**：我们存 Key 出问题要担责
- ✅ 缓解：仅存系统钥匙串（Keychain/DPAPI/libsecret）+ 不开任何遥测 + 隐私政策背书

### 反对意见（备选考量 2）

- ❌ **失去 Token Plan 这类"内嵌计费"的便利**：托管模型用户不用绑卡
- ✅ 缓解：可选"官方中转"功能（见 ADR-002），按量计费，默认关闭，给不愿绑卡用户备用

## 后果

- 技术实现：必须做 Provider 适配层（OpenAI 兼容 / Anthropic / Gemini / 自定义 / Ollama）
- 模型配置页面是**灵魂页面**——必须做好（PRD §5.3 ④）
- 首次引导要把"零 Key 体验"放在第一选项
